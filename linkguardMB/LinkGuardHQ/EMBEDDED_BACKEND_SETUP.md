# LinkGuardHQ — Embedded Backend Setup Notes

This document describes the **manual Xcode-side steps** required after the
source code has been generated by the integration commit. The Swift sources
have already been added to the repository, but Xcode does not auto-discover
new files; you must add them to the target.

## 1. Add new Swift sources to the `LinkGuardHQ` target

Drag-and-drop (or `File → Add Files…`) these files into the `LinkGuardHQ`
group, making sure **Target Membership** has `LinkGuardHQ` checked:

- `BackendSupervisor.swift`
- `BackendMode.swift`
- `HQBackendServicesView.swift`
- `HQSettingsView.swift`
- `HQDecisionHistoryView.swift`
- `SetupAssistantView.swift`

## 2. Embed the Python backend as a bundled resource

The supervisor looks for the backend in this order:

1. `~/Library/Application Support/LinkGuardHQ/backend/`  (user-writable copy)
2. `Bundle.main.resourceURL/backend/`                    (read-only template)
3. Dev fallback `../../../macos` relative to the running binary

To enable option 2 (recommended for distribution):

1. In Xcode → project navigator, right-click the `LinkGuardHQ` group → **Add Files to "LinkGuardHQ"…**
2. Select the repository's `macos/` folder.
3. In the import sheet:
   - **Create folder references** (so it stays as a `backend` blue folder, not a yellow group)
   - **Copy items if needed**: unchecked (we want it to track the repo folder)
   - **Add to targets**: `LinkGuardHQ`
4. Rename the added folder reference to `backend` (right-click → Rename in Xcode).
5. Build phase **Copy Bundle Resources** should now contain the `backend`
   folder reference. Confirm it is listed there.

On first launch, `BackendSupervisor` will detect the bundled copy and may
optionally rsync it into `~/Library/Application Support/LinkGuardHQ/backend/`
so users can edit configs without re-signing the app.

## 3. Disable App Sandbox

Already done in `LinkGuardHQ.entitlements`:

```xml
<key>com.apple.security.app-sandbox</key>
<false/>
```

If you ever re-enable sandbox you **must** add a `com.apple.security.temporary-exception.files.absolute-path.read-write` entry for the backend dir, and you still cannot spawn Python/Ollama from a sandboxed binary. So keep it disabled.

## 4. Required system tooling on the user's Mac

The Setup Assistant (`SetupAssistantView`) automates these, but for a manual
verify run from Terminal:

```sh
brew install python@3.11 ollama
ollama serve &
ollama pull gemma4:e4b
cd ~/Library/Application\ Support/LinkGuardHQ/backend  # or repo macos/
python3.11 -m venv ../.venv
../.venv/bin/pip install -r requirements.txt
```

## 5. Info.plist additions (only if hardening signing later)

If you sign with `--options=runtime` (Hardened Runtime), add in
`Info-HQ.plist` (or via Xcode Capabilities):

- `com.apple.security.cs.allow-jit` → `true`  (some Python wheels)
- `com.apple.security.cs.allow-unsigned-executable-memory` → `true`
- `NSAppleEventsUsageDescription` → "Used by LinkGuardHQ to launch the embedded Python backend."

## 6. Build & smoke-test

1. `Product → Clean Build Folder`
2. Build `LinkGuardHQ` for **My Mac**.
3. First launch: open **Settings → Backend** in the sidebar.
4. Backend Mode = **Embedded** → Setup Assistant should run all four steps.
5. Open **Backend Services** sidebar item — all 9 services should turn green within ~30 s.
6. Open **AI 決策歷史** — initial list will be empty until the field app reports something.

## 7. Switching to remote backend

If a user prefers running the backend on another Mac (or the original Windows
PC), they pick **Backend Mode → Remote** in Settings, fill in the host, and
the supervisor will stop any local services automatically.
