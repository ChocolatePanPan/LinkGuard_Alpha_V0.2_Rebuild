## 權限設計修正（ICS／消防實務）

### UCC（Unified Command Center）

- 負責跨區域戰略協調與資源調度
- 不直接修改第一線地圖標記
- 主要負責：EMIC、PWS、AI 分析、多 SCC 管理
- 避免直接介入現場細部操作造成指揮衝突

### SCC（Site Command Center）

- 現場真正核心指揮層
- 負責分區建立、危險區管理、搜救狀態發布、撤離路線、任務派遣
- 為 ICS 架構中的戰術控制核心

### TL（Team Leader）

- 以「現場帶隊」為核心
- 可建立臨時子區與局部標記
- 不可直接修改正式災區主分區
- 主要負責 TE 管理、傷患建立、搜救回報、現場任務執行

### TE（Team Member）

- 第一線搜救人員，功能應極度簡化
- 核心能力：SOS、危險點回報、GPS 定位、照片回報、語音回報
- 不進行正式地圖規劃與分區操作

### EMT（Emergency Medical Team）

- 不參與主搜索，專注於 START 檢傷、傷患更新、後送管理、生理監測
- 以醫療資訊流為主

### VO（Volunteer）

- 僅提供輔助支援，不接觸完整戰術資訊
- 核心功能：災情回報、物資支援、多語翻譯、集合通知
- GPS 僅上傳自身位置，不可查看他人，避免個資與指揮資訊外流

| 狀況 | 自動接管者 |
|------|------------|
| TE 失聯 | TL 接管 |
| TL 失聯 | SCC 接管 |
| SCC 離線 | UCC 接管 |
| UCC 斷線 | 備援 UCC 接管 |
| EMT 失聯 | SCC 重新分派 |

## 資料可信度分級

| 回報來源 | 等級 | 說明 |
|----------|------|------|
| SCC 確認 | S | 指揮中心正式確認 |
| TL 現場確認 | A | 小隊長確認資訊 |
| TE 現場回報 | B | 第一線搜救回報 |
| AI 辨識結果 | C | AI 推論資訊 |
| 志工回報 | D | 未確認民間資訊 |

## 高壓環境設計原則

| 模式 | 用途 |
|------|------|
| 高壓模式 | 僅保留核心功能 |
| 夜間模式 | 高對比低亮度 |
| 手套模式 | 超大按鈕操作 |
| 離線模式 | 本地資料暫存 |
| 緊急模式 | 一鍵 SOS 與語音輸入 |
| 低電量模式 | 關閉非必要功能 |
